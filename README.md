# china-accounting-sample-data

**中国口径、勾稽自洽的会计/社保样例数据生成器——像数学例题一样的人造数据。**

给会计 / 代账 / 发薪类软件做演示和测试时，最难的不是造数，而是造出**口径正确、表与表之间严格勾稽**的数据。网上几乎没有现成的中国口径完整数据集，随手编的数又经不起对账。本项目用代码生成一份「数学例题」级的样例工作簿：每一笔金额都按中国社保/公积金/个税规则计算，五个业务表之间逐月对账、内置 103 项勾稽校验，**跑通即自洽**。

## 它能生成什么

一个 `.xlsx` 工作簿，7 个 sheet，表头使用中国实际报表用语：

| Sheet | 内容 | 规模（默认案例） |
|---|---|---|
| 员工花名册 | 编号/脱敏姓名/脱敏证件号/入离职/月薪/核定基数/卡号/专项附加扣除 | 8 人 |
| 工资表 | 逐月：应发 → 代扣五险一金（分险种）→ 累计应纳税所得额 → 当月个税 → 实发 | 12 月 × 8 人，87 行 |
| 社保公积金缴纳明细 | 分险种、单位/个人比例与金额，补缴单列 | 70 行（含补缴）＋公积金 12 行 |
| 银行流水 | 工资每月 10 日代发、社保次月 12 日税务划扣、公积金当月 15 日汇缴 | 112 笔 |
| 银行回单 | 工资/社保/公积金每月各一条，编号规则化 | 112 条 |
| 勾稽校验 | 逐月横向对账，全部 ✓ 才允许导出 | 103 项 |
| 口径说明 | 参数来源（官方文件号）、边界场景规则依据、简化假设 | — |

默认案例（全部虚构）：**北京虾米科技有限公司**，2025-07 ~ 2026-06 共 12 个费款月，含典型边界场景：

- **员工02** 月薪 7000 元 < 北京 2025 社保基数下限 7162 元 → 按下限封顶；7-8 月按旧下限 6821 预缴、10 月统一补差（官方过渡期规则）；
- **员工07** 2026-01-12 入职 → 入职当月参保、次月扣款（北京「当月参保、次月缴费」）；
- **员工03** 2026-03-20 离职 → 离职当月工资照发、社保缴至当月，次月停；
- **员工08** 月薪 8000 元 > 下限 → 不触发封顶，作对照。

## 口径来源（官方公开数据优先）

| 参数 | 取值 | 来源 |
|---|---|---|
| 社保基数上下限 | 上限 35811 / 下限 7162 | 京人社发〔2025〕11号（2025-09-17 发布，自 2025-07 执行） |
| 过渡期 | 7-8 月按旧下限 6821 预缴、10 月补差 | 同上通告原文规则 |
| 公积金 | 上限 35811 / 下限 2540、比例 5%~12% 取 12% | 北京住房公积金管理中心 2025 年度通知（2025-09-18 发布） |
| 养老 | 单位 16% / 个人 8% | 国家统一费率 |
| 医疗（含生育） | 单位 9.8%（9%＋0.8% 合并征缴）/ 个人 2%＋3 元大额互助 | 北京现行口径 |
| 失业 | 单位 0.5% / 个人 0.5% | 国家统一费率 |
| 工伤 | 单位 0.4%（二类行业基准） | 北京 2025-01-01 起停止阶段性降费，按全国基准 |
| 个税 | 累计预扣法、5000 元/月、专项附加扣除 | 国家税务总局公告 2018 年第 61 号、国发〔2023〕13 号 |

交叉参考的开源实现：[ikiwihome/income-calc](https://github.com/ikiwihome/income-calc)（北京历年基数）、[IMMKF3/Mocent](https://github.com/IMMKF3/Mocent)（五险比例）、[Rachel030219/ChinaPayrollCalculator](https://github.com/Rachel030219/ChinaPayrollCalculator)、[carlchai/cctax](https://gitee.com/carlchai/cctax)（个税步骤）。2026 年度新参数尚未公布时沿用 2025 年度值并在口径说明中注明。

## 勾稽清单（内置自验，不平即抛异常）

1. 逐费款月：工资表代扣五险（分险种）个人合计 ＝ 社保明细个人部分合计；
2. 逐费款月：工资表代扣公积金个人合计 ＝ 公积金明细个人部分合计；
3. 逐扣款月：银行流水社保扣款 ＝ 社保明细（费款所属期＝上月）合计；
4. 补缴流水 ＝ 社保明细补缴行合计；
5. 逐月：银行流水公积金汇缴 ＝ 公积金明细合计；
6. 逐发放月：银行流水代发工资 ＝ 工资表实发合计（所属期＝上月）；
7. 全年汇总：实发 / 五险一金 / 社保（含补缴）/ 公积金 / 流水总额交叉核对；
8. 行级断言：每行小计、实发 ＝ 应发 − 五险一金 − 个税、个税累计预扣一致性。

## 脱敏规范

人名（王\*敏 等占位名）、证件号（110\*\*\*XXXX）、银行卡号、公司/专户账号**全部虚构**；不采集、不包含任何真实个人信息。如与真实主体巧合，纯属偶然。

## 用法

```bash
pip install -r requirements.txt

python main.py                                  # 输出 ./output/样例数据.xlsx
python main.py --out 我的样例.xlsx --csv-dir ./csv   # 指定输出与中间 CSV
```

运行时会先执行全部勾稽断言，任何一项不平直接报错退出——**导出的文件必然自洽**。

## 换城市 / 年度 / 人数

所有口径参数集中在 `src/config.py`：仿照 `beijing_2025_config()` 写一个新的 Config 函数即可——基数上下限、各险种比例、公积金比例、个税表、期间（起始年月/月数）、员工花名册（人数随意增删）、过渡期补差规则都是配置项。生成层与校验层按 Config 通用运行。

## 目录结构

```
├── main.py            # 一键运行（生成 → 勾稽自验 → 导出 xlsx/CSV）
├── src/
│   ├── config.py      # 配置层：城市/年度/期间/比例/员工/过渡期（全部可配）
│   ├── generator.py   # 生成层：逐月计算工资/社保/公积金/流水/回单
│   ├── validator.py   # 校验层：103 项勾稽断言，不平即抛异常
│   ├── excel.py       # 渲染层：单工作簿 7 个 sheet
│   └── notes.py       # 口径说明 sheet 内容（随 Config 参数化）
├── sample/            # 生成的样例工作簿
└── requirements.txt
```

## 已知简化假设

入职/离职当月均按全月计薪；社保分项按「基数×比例」四舍五入到分、公积金按北京规则取整到元；个税按工资实际代扣口径逐月累计预扣。均记录在「口径说明」sheet。
